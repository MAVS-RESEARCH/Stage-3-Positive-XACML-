## Mission

Answer one narrow reviewer-critical question (spec §0, §3):

> Can an independently engineered authorization system and its pre-existing governing specification/configuration naturally supply enough semantic information for PC to point-identify a nontrivial resource-freezing signature, without PC inventing the authorization-admission, certificate-representation, authority, or action/checkpoint boundaries after observing the result?

Formal question: let `Omega_ext` = frozen XACML standard + AuthzForce release/config + policy + original request + expected response; `Omega_exp` = preregistered wrapper (two latent worlds, unit-cost repair action, freeze-mask order, exact solver conventions, recording format); `Omega_star = Omega_ext ∪ Omega_exp`. Does `Omega_star` fix the PC semantic interface so that `|K_{Pi,Omega_star}| = 1` with a nontrivial all-freeze signature, without manual E/R/A labels?

Preregistered positive prediction (must be allowed to fail):

```text
T(q_supply_missing_attribute) = {E}
K_Pi = [1, INF, 1, 1, INF, INF, 1, INF]
|K_{Pi,Omega_star}| = 1, classification = STRUCTURAL_E_TOUCH_DEPENDENCE
```

Success is only `POSITIVE_NATIVE_STAGE3` if all 10 conditions in spec §8.1 hold. Any anchor ambiguity → `NATIVE_ANCHOR_INSUFFICIENT`. This is a source-native positive witness for D33 Stage III, paired with Polaris (natural negative) and PC-TAU (controlled geometry); it is not a prevalence, benchmark-superiority, safety, causal, or mechanism claim (spec §1.3–1.5, §17–§19).

**Claim-scope lock (`Omega_ext` vs `Omega_exp`).** The permitted positive claim is exactly: external semantics anchor the measured interface, while the finite measurement wrapper itself (two latent worlds, unit-cost repair, freeze order, solver conventions, recording format) is experiment-authored. It is never: "XACML natively defines PC's exact repair action." The correct decomposition, per the controlling spec ("the orchestration layer may construct the standard request but may not perform authorization logic"; Atom acceptance requires only the request/response boundary itself to be independently supported), is:
`Atom` = native XACML request/response transaction [N1]; `Q`/wrapper = construct completed request + invoke Atom [N1+X].
`NATIVE_TRANSACTION_PROVEN + RECONSTRUCTION_AS_WRAPPER` is a fully valid positive configuration — `COMBINED_BOUNDARY_PROVEN` is NOT required and must not be demanded — provided (i) the native transaction boundary is externally supported, (ii) the wrapper merely constructs the standard request, (iii) it performs no authorization logic, and (iv) the wrapper/action definition was preregistered. Atom fails only if the native transaction itself lacks external support or the wrapper exceeds mere construction (see Phase 2).

## No-Model-Training Policy and Anti-Circularity Contract

There are no trainable ML models in this experiment. The decision function is the frozen external AuthzForce PDP + frozen policy; the PC harness is deterministic rule code (canonicalization, parser, exact solver). Therefore there is no training, no held-out data, no benchmark suite in the ML sense, and nothing here tests generalization. The forbidden phrases "training benchmark," "held-out benchmark," and "different benchmarks" are not used in this plan; what follows uses only: sealed expectation, implementation verification, falsification controls, sensitivity analyses, and anti-circularity tests. Dual implementations demonstrate computational correctness (two codebases, one result), not generalization.

- No training run, no hyperparameter tuning, no validation-based selection exists. `prereg/expected_signature.json` + `prereg/experiment.yaml` are a sealed expectation: frozen in Phase 1 before any touch/K computation and never imported by computation modules. Their role is temporal ordering against circularity, not a train/test split.
- The implementation-verification and anti-circularity program consists of:
  - Source-integrity checks: 4/4 fixture byte-mutations + spec-file mutation must trip the hash verifier (integrity gate, not a K gate).
  - Semantic canaries with preregistered exact outcomes: `MustBePresent` removed/changed, wrong Category, wrong DataType, irrelevant extra attribute — none reuse the primary `x_permit`/`x_nonpermit` pair as success criteria; each asserts a sealed exact decision/status/error class or projection-stability property (see Phase 5).
  - Semantics-preserving perturbation checks: whitespace / order / formatting / path-relocation variants assert H/P_R/Lambda/T/K invariance.
  - Interface-change negative control: explicitly labeled `OUT_OF_SCOPE_INTERFACE_CHANGE` split (`q_construct_attribute` + `q_submit_request`) asserting `INTERFACE_CHANGED / THEOREM3_INVARIANCE_NOT_APPLICABLE`, never compared as a T3-equivalent K.
  - Cost sensitivity checks: 0.5 / 2 / 10 assert structural E-dependence invariance (finite entries rescale, E-freezes stay INF).
  - Negative-world sensitivity checks: sealed `wrong-answer-1`, `wrong-answer-2` (plus any further strings frozen before execution) assert continued `NotApplicable` and open-fiber preservation without replacing primary `x_nonpermit`.

  - Leakage check: dependency-graph proof that `expected_signature.json` is read only by final comparison.
  - Clean-reproduction check: fresh checkout rerun must yield byte-identical canonical result (modulo excluded run metadata).
- Circularity analogues and defenses: post-hoc boundary selection (T1) → ledger frozen before touch plus blind adjudication (Phase 2B); manual labeling (T2) → action-specific-assignment scan + independent derivation; middleware semantics (T3) → immutability + Lambda hash equality; cost cherry-pick (T4) → cost sweep; hidden authority (T5) → Lambda hash; string-presence shortcut (T6) → category/datatype canaries; atomicity laundering (T7) → interface-change control; leakage (T8) → dependency audit; drift (T9) → pinned commit + re-verify every phase; relabeling (T10) → preregistered targets + abort.

## Phase 2 — Source-Native Semantic Anchor Audit (incl. 2B blinded adjudication)

Scope: the most important phase — decide whether external semantics actually fix H, P_R, Lambda, Atom (plus omega/Q/Succ+/c/A_Pi/terminal-open) before any touch/K is computed (spec §§4–5, 12). No E/R/A/touch/Delta/freeze values may appear in extraction code. Any anchor needing "we choose to regard…" without N1/N2/N3 → `AMBIGUOUS` → top-level `NATIVE_ANCHOR_INSUFFICIENT`, stop positive claim (spec §2.8).

**Why Phase 2 is split.** Everything after Phase 2 is comparatively easy: once a complete contract with externally justified H, P_R, Lambda, Atom exists, touch derivation is mechanical and the eight-freeze result is near-trivial — that is by design, since the experiment tests Stage-III external anchoring, not mathematical difficulty. The hard gate is therefore inside Phase 2: the same party who knows the desired answer (`{E}`, singleton K) must not be the sole judge of whether the external evidence counts as sufficient. A code-level non-leakage rule does not eliminate semantic confirmation bias (`expected {E} → choose defensible-looking H/P_R/Atom → {E}`). Phase 2B below is the defense. It is not a seventh implementation phase; it is part of Phase 2.

**Protocol Amendment 001 (operative for this execution).** The original protocol required a qualifying independent second human adjudicator.
